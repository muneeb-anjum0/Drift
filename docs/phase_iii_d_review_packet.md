# Phase III-D blind label review packet

The proposed retrieval cases are in [`retrieval_review_draft_v1.json`](../evaluation/phase_iii_d/retrieval_review_draft_v1.json). This file is **not** a final test. Its 40 query messages, 40 new baseline requirements, category tags, and target IDs were generated by an AI assistant from the previously frozen [`blueprint_v1.json`](../evaluation/phase_iii_d/blueprint_v1.json). The proposed target IDs are not independent human ground truth.

## Reviewer task

Review each project's ten requirements and ten messages. For every query, record all baseline requirement IDs that the message materially affects, or an empty list if none. Use the Phase III-C [retrieval labeling guide](phase_iii_c_dataset_foundation.md). Review without seeing R0/R5 rankings, scores, or predictions. Record uncertainty rather than forcing an answer.

The draft has specific review notes for `mp-q06` (whether booking confirmation relates to decision-status email) and `eo-q02` (the exact 48-hour refund boundary). Also examine `eo-q07` (finance role versus report access) and all zero-target and multi-target cases closely. A revised label or exclusion must be documented before the final dataset is hashed and evaluated.

For each query, a reviewer should provide:

```json
{"case_id":"mp-q01","reviewer_expected_requirement_ids":["mp-plan"],"decision":"CONFIRMED","note":"..."}
```

Use `decision` values `CONFIRMED`, `REVISED`, `AMBIGUOUS`, or `EXCLUDE`. A separate reviewer name or stable pseudonym and review date should accompany the decisions. An `AMBIGUOUS` case cannot be used as strong correctness evidence until adjudicated. A second reviewer is preferred for contested cases.

## Pre-prediction audit

The draft follows the frozen target-count plan: eight zero-target, twenty one-target, ten two-target, and two three-target queries. A mechanical comparison found no exact or high-similarity query or requirement text overlap with the repository's raw/retrieval development, oracle, or closed-final JSON datasets; no new query text appears verbatim in the two historical benchmark source files. This does not establish semantic or original-training independence. The original LoRA training examples are unavailable.

No R0, R5, V3, or oracle prediction has been run on the draft. Once human decisions arrive, the reviewer decisions and any adjudication will be stored separately, the final dataset will be versioned and hashed, and the frozen gates in [`gates_v1.json`](../evaluation/phase_iii_d/gates_v1.json) will be applied without changing the cases after results are visible.
