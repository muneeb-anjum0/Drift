## Task, benchmark and leakage boundary

Retrieval maps one client message and N baseline requirements belonging to the authorized project/version to zero or more materially affected requirements. The Go service authorizes and selects an immutable baseline before retrieval, scores all nonempty title/description entries, applies relevance gate/threshold/cap, then invokes the unchanged classifier **once per selected requirement**. Retrieval does not determine the six-class relationship. Candidate generation, representation, ranking, threshold/calibration, budget and classification were analyzed separately. No production retrieval, authorization, tenant, persistence, prompt, postprocessor, inference or model code was changed.

The preregistered [plan](phase_iii_f_study_plan.md) precedes predictions. New [scaling development corpus](../evaluation/phase_iii_f/scaling_dev_v1.json) SHA256 `c4446a726838c6dbefa655a1762ce920b3aec8ffd15aeef2c2b9b4790d9ae382` was frozen in commit `8790ad0` before scoring. It has 9 nested sizes (5, 8, 10, 16, 20, 32, 50, 75, 100), ten **fixed** synthetic queries per size, two zero-target queries, and one-/two-/three-/four-target cases. Requirements comprise five core farm entries, four authored same-domain/semantically adjacent distractors, 27 other farm requirements, then open-development cross-domain distractors. Every query records ID, project/size, text, expected IDs, category, `SYNTHETIC` provenance, generation method and notes; every requirement records source. Those 90 rows are **ten paired query controls, not 90 independent observations**. N>36 is optimistic because distractors are mostly cross-domain. Labels are single-author synthetic, not independently reviewed; broad query/materiality uncertainty is possible.

The aggregate-only [contamination audit v2](../evaluation/phase_iii_f/contamination_v2.json) found zero exact and zero token-Jaccard≥.8 query pairs against older development, historical raw/final, III-D closed, III-E closed, prompt examples and repository tests. It did not expose closed records. Requirement reuse from open development is intentional; original adapter-training overlap remains **UNKNOWN**. Audit v1 undercounted prompt examples; v2 fixes that audit without changing frozen corpus bytes. No independent final set was built, because no R7 earned one.

Reproduction uses the frozen corpus bytes: run `phase3f_scaling_dev.py --output ...` and verify its SHA256; run the unchanged Go `cmd/eval-retrieval` at frozen R0 commit and current R5 source with `.25/3`; run `phase3e_semantic_dev.py` with `CUDA_VISIBLE_DEVICES=''` and the pinned locally cached encoder for R6 and `--decompose`; run `phase3e_bm25_dev.py` at `.05` from the R5 trace and `phase3e_hybrid_dev.py` from R5/R6 traces. Finally run `phase3f_compact.py`, `phase3f_analyze.py --directory evaluation/phase_iii_f --output evaluation/phase_iii_f/architecture_study_v1.json`, and `phase3f_open_ceiling.py`. ## Existing architecture and the gate

R0/R5 tokenize lowercase alphanumeric text, remove stopwords and normalize simple plurals; R5 adds limited verb suffixes and 13 aliases. They score description/title/domain token-set overlap with a conditional bonus, a specific-match gate, threshold .25, stable ties and cap three. R6 is a small offline semantic encoder, not product-integrated. Existing acceptance is ≥90% overall target-link delivery and ≥85% for every measured project size. `docs/model-acceptance-criteria.md` introduced these numbers in commit `66bb5fe` after V0 baseline measurement; the documented rationale is that the classifier cannot recover a requirement it never sees. No product loss/cost model or measured derivation of **90 rather than 80/95** is documented. Classification: **CONSERVATIVE-HEURISTIC** (protective product concern, quantitative level not empirically established), not a reason to lower it after failures. At 80%, the synthetic R6 panel's frozen selected 113/135 (83.7%) would pass overall yet miss 22 links; at 90% it fails. At 95%, top-three ranking also fails (122/135=90.4%), and a larger budget would expose many irrelevant candidates. These are development counterfactuals, not end-to-end measured outcomes.

A four-target message is **structurally impossible** to fully reach with a cap of three.

For the scaling panel R6's minimum threshold-free k for 70/80/85/90/95/100% link recall is 2/3/3/3/5/8. These are oracle budgets. At k=3, 90 queries require 270 model calls and expose 148 false candidates; at k=5, 450 calls and 319 false candidates; at k=10, 830 calls and 695 false candidates. Thus k=5 recovers 9/135 links over k=3 at +180 calls and +171 false exposures. A model call is a sequential 7B CPU inference in the current product; these counts are exact candidate counts, **not** measured wall-time predictions. Historical single-slot inference means cost could be large, but an end-to-end scaling latency was deliberately not measured because 7B execution was out of scope. The [Pareto points](../evaluation/phase_iii_f/architecture_study_v1.json) use recall, call count and false exposures; tied/dominated points do not prove a deployable policy because threshold-free selection forces irrelevant candidates.

Max-selected=3 is a **meaningful structural limit**, especially for four-target queries, but **not the primary observed historical delivery bottleneck**: new R6 selected 30/40 versus rank-top-three 37/40 (7 losses before selection) and rank-top-five 40/40 (3 more cap losses); older R6 selected 61/74 versus rank-top-three 69/74 (8 before selection) and rank-top-five 73/74 (4 more cap losses). Raising k alone without calibration would be expensive. The existing 90% gate remains unchanged.

## Scaling, zero-target and multi-target behavior

R0 selected target hits fell from 12/15 at N=5 to 11/15 at N=100; R5 from 12/15 to 9/15; R6 from 13/15 to 12/15. R6 threshold-free top-three fell from 14/15 to 13/15, and top-five from 15/15 to 14/15. The 8→32 transition adds mostly farm-domain competition, while >36 mostly adds cross-domain requirements; it is **not** evidence of robustness to 100 truly hard same-domain requirements. False exposures rose with size: R5 selected false candidates 6 at N=5 versus 14 at N=100; R6 8 versus 10. R6 zero-target selection changed from 0/2 queries at N=5 to 1/2 at N≥32; across all sizes 4/18 zero-target instances were exposed. R6 selected 23/36 four-target links, with the cap explaining at least one loss per repeated case; top-five reached 32/36. All size/target-count numerator-denominator splits are in the machine report.

Score distributions overlap: across 135 positive and 3,025 negative R6 requirement/query pairs, median cosine was about .601 versus .167, but positive minimum .410 was below frozen .45 and negative maximum .643 exceeded it. The all-pairs median conceals hard competitors; one global threshold is therefore not proven calibrated. Project-size-specific thresholds would be post-hoc on this small synthetic panel and were not introduced. Lexical scores have many exact zeros/ties; ranking them at k=8/10 can create apparent recall by baseline-order accident. A rank-top-k hit with zero score is not meaningful retrieval. Numbers, IDs, units and negation were only partially stressed by this panel; no robust structured-signal claim is made. No giant synonym dictionary or benchmark-specific patch was added.

## Architecture-family results

- **F-BM25-1:** Reused the preregistered Phase III-E simple binary-term-frequency BM25-style research baseline over R5-normalized title+description token union, `k1=1.2`, `b=.75`, smoothed IDF `log(1+(N-df+.5)/(df+.5))`, score normalized by summed query IDF×2.2, .05 research threshold, cap three, stable source-order ties. On scaling it selected 108/135 with 91 false exposures; new development 28/40 with 19 false, older 59/74 with 29 false. Ranking gains at top five do not translate to a safer selected system. **Not supported over R6.** BM25 here is an existing research implementation, not a newly introduced package or product dependency.
- **F-SEM-1:** Reused the pinned CPU MiniLM R6 control, no tuning or new weight. Scaling selected 113/135 with 80 false; new development 30/40 with 7 false, older 61/74 with 19 false. Semantic rank helps some low-overlap cases, but the unchanged independent Phase III-E decision was already NOT SUPPORTED. This study does not rerun that holdout or overturn it.
- **F-HYB-1:** Existing coarse `0.5*R5 + 0.5*max(0,cosine)` research grid point with threshold .35 and cap three yielded scaling 104/135 with 77 false; top-five 135/135 only by 450 calls/315 false. New development selected 30/40 with 8 false, older 63/74 with 38 false. No stable material low-cost gain; **reject as R7 basis**.
- **F-2STAGE-1:** Derived BM25 top-5/10/20 admission, then frozen semantic ranking and .45/cap-three selection. Top-10 selected scaling 113/135 with 79 false versus R6 113/135 with 80; new development 30/40 with 7 false versus R6 30/40 with 7; older 61/74 with 18 false versus 19. This one-false-candidate difference is not meaningful. Since full project requirement embeddings can be cached once per baseline, a per-query BM25 prefilter may not even reduce encoder work; it adds first-stage ranking and can irreversibly drop targets. **No two-stage architectural support.**
- **F-DECOMP-1:** Existing deterministic split on comma, semicolon and standalone `and`, retaining the whole query and only ≥3-word clauses; max cosine, .45/cap-three. Scaling selected 109/135 with 84 false versus whole-query 113/135 with 80. New development reached 32/40 with 8 false versus 30/40 with 7, but older fell to 60/74 with 23 false versus 61/74 with 19. Cross-corpus instability and extra exposure **reject** decomposition as R7 basis. It did not invent intents, but simplistic split is not safe evidence of semantic decomposition.
- **F-REPR-1:** BM25 title-only ranked 104/135 at top three on the synthetic panel but selected just 14/135 at the same normalized .05 threshold; description-only and title+description each selected 108/135. On new development title-only selected 11/40, older 14/74; description-only matched the BM25 union's selected counts. A title-only threshold would need recalibration; this controlled result does not prove title text useless. Production description/title fallback was unchanged. Acceptance criteria and other structured fields were not invented for production.

The in-memory semantic encoder is a pre-existing offline dependency, not a new service, cloud API or vector database. The pinned [official model card](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) identifies Apache-2.0 licensing, 384-dimensional vectors and semantic-search use. The existing `torch`, `transformers`, tokenizer and artifact revisions are recorded in the R6 freeze; no package or model was added to product manifests. Missing/corrupt weights, NaN/dimension mismatch or stale cache should fail explicitly in any eventual production design; the current research scripts do not implement a production fallback. Cached requirement vectors would be invalidated by authorized project, baseline version, text, encoder revision or pooling/normalization changes. No persistence was added.

Resource probe on the N=100 project (local warm OS cache; imports excluded): pinned model load after import ~0.14 s, 100-requirement embedding index ~0.36 s, ten-query batch ~0.035 s, sequential warm query plus 100 similarities ~0.0099 s/query; peak Python RSS ~809 MiB, requirement float32 vectors 153,600 bytes, local cached weight directory ~88 MiB. Full 406-text batch including model load in the existing evaluator took ~5.37 s, peak ~815 MiB. These are process/microbench observations, **not** end-to-end product latency or a true disk-cold startup measurement. No GPU or 7B classifier was used. No source or dependency upgrade was required. CPU utilization was not separately profiled.

## Decision, verification and limitations

**Architecture decision: NO ARCHITECTURE YET SUPPORTED.** The clearest measured issue is selection calibration, with a meaningful but secondary top-three constraint; ranking is imperfect but often places targets in the first five. Growing candidate budgets can cross 90% ranking recall but at unacceptable unqualified false-exposure/model-call cost. BM25, semantic, hybrid, two-stage, decomposition and representation variants do not show a substantial, coherent, cross-corpus, low-cost improvement sufficient to freeze R7. **R7 was not created; no new independent holdout, review, blind evaluation, oracle classifier test, V3 or end-to-end test was authorized.** Retraining remains **NOT YET JUSTIFIED** because independently reliable retrieval has not been established and no recurring post-oracle semantic classifier failures were isolated. No model training, GPU, promotion or release occurred.

Verification: frontend `npm ci`, lint, typecheck, build and high-severity audit passed (zero vulnerabilities); Go format/vet/test/build and live Mongo integration passed in Go 1.26.6 Alpine; `govulncheck` reported zero called/imported-package vulnerabilities and one required-module advisory not reached by code. Python inference and new research tests passed (15/15), scoped Ruff/compile and `pip-audit` passed; Q4 guard and CPU/GPU Compose static validation passed. Ruff scope excludes ignored local `tools/model/vendor/llama.cpp`, matching CI's repository-owned checkout. CI's `software`, `integration` and `e2e` results must be recorded after PR verification; do not infer them from local checks. New tracked files are development data, tools, report and registry only; no Go/React/FastAPI source, dependency manifest, acceptance gate, model configuration or closed dataset was modified.

Known unknowns: real requirement-size distribution; inactive/rejected baseline semantics; independent labels for hard same-domain 50–100 requirement projects; target/false-exposure product loss ratio; quantitative basis for 90%; adapter-training overlap; 7B end-to-end latency at larger budgets; true cold-start/resource behavior; structured identifier/negation performance and any prospective confidence intervals. Next phase should start with a human-reviewed, development-only hard same-domain scaling corpus and an explicit product cost/recall tradeoff, then consider calibrated zero-target abstention separately from ranking. Do not mine the closed III-D/E cases or create an R7 from this report alone.
