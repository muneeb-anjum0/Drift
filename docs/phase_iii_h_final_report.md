## Contracts, ownership, and pre-result gate

Current product P1 asks for `label`, `confidence`, `reasoning`, and `changed_elements`. FastAPI receives raw text, its `parse_prediction` accepts exact JSON or extracts a JSON object and normalizes bounded variants, then Pydantic validates; Go validates the normalized response before Analyze/Save workflow ownership. Product raw model text is not a persisted scientific trace. Product defaults remain singleton P1; no experimental batch request is wired to FastAPI or Go. The H runner captured each raw `/completion` response and generation metadata before strict parsing. Its validator rejects duplicate JSON keys, wrong types, missing/foreign/duplicate IDs, extra fields, invalid six-class labels, and nullable-rule violations; no silent label or ID invention, partial-batch acceptance, or normalization is permitted. Failed research batches are atomic failures with no persistence. Trusted IDs are drawn from the frozen case input, never model-supplied. The original G array requires one ordered `{id,affected,label}` per candidate; `affected=false` mandates `label=null`. H-MAP-v1 requires one property per supplied ID under `results`, with a canonical label or `null` for unrelated candidates. `unchanged` is a valid six-class label but **not** a substitute for unrelated/null.

The [frozen gate](phase_iii_h_study_plan.md) requires P1 raw 12/12 plus three valid repeats; each attempted batch size 2/3/5 must be raw exact-ID 4/4, and batch development support requires at least 24 varied raw-valid calls **and** no material semantic regression, no runtime/resource failure. This is distinct from the older 90% retrieval gate. A perfect 24/24 observation has an approximate 95% Wilson lower bound of only 86.2% even if calls were independent; here four examples were repeated, so the effective independence is lower. It cannot establish production reliability.

## Phase III-G failure isolation

The [historical reclassification](../evaluation/phase_iii_h/g_failure_taxonomy_v1.json) preserves all eight original raw-output references and hashes: 8/8 complete syntactically valid JSON; 2/8 exact G contracts; four omitted required results, two used `affected=false` with `label="unchanged"`. Outputs used 18–46 of 120 allowed tokens. No historical duplicate/foreign ID, invalid enum, timeout, truncation, or parser defect explains the six failures. The strict parser correctly failed closed. The plausible source is unconstrained model compliance plus redundant boolean/nullable contract complexity; that is an inference from the observed outputs, not proof about the model in general.

The pinned [llama.cpp server README](https://github.com/ggml-org/llama.cpp/blob/bd4f514db14d87fded667787a7a963bfbaa98e89/tools/server/README.md) documents request-scoped `/completion` `json_schema` and `grammar`. This exact running image accepted and returned schema-constrained H-C0, H-C1, and H-D2 requests. The G JSON schema constrained field types/count/enum but could not express the conditional `affected=false ⇒ label=null` in the tested schema, and model outputs violated that cross-field rule. The H-MAP schema declared each trusted ID required and `additionalProperties=false`; the independent strict validator remained authoritative. No runtime/configuration change was necessary.

This is development-case batch interference, not independently measured generalisation. Candidate selection/retrieval recall was not rerun, and no end-to-end product quality claim follows.

## Repair, retry, and decisions

No code-fence/whitespace-wrapper or malformed JSON failure was observed, so H-F1 syntax-only repair was not attempted; inventing IDs/results or relabeling `unchanged` to `null` would be semantic mutation and is prohibited. H-E1 one-retry experiment was not run: the best structural configuration H-D2 had no structural failures to retry, while the G failure mode was systematic conditional-label noncompliance and a generic retry could not be credited as a fix. Raw, repair-assisted, and retry-assisted rates are therefore **not interchangeable**: raw figures above are measured; assisted rates and costs are NOT MEASURED, not 100%. A future retry design requires a separate preregistered failure population, bounded latency/cost, idempotence, and no label hints.

Decisions: **SINGLE-ITEM STRUCTURAL RELIABILITY DEVELOPMENT-SUPPORTED on the 12-case open panel**, not production guaranteed; **BATCH CONTRACT/PIPELINE NOT SUPPORTED** because the required semantic non-regression gate fails even though H-D2 achieved 24/24 raw structure. Parser contribution: no demonstrated defect; strict rejection was correct. Unconstrained model compliance: material G array failure source. Truncation: not implicated in observed failures. Constrained generation: supported by pinned runtime and useful for exact shape, not sufficient for affectedness semantics. Repair: NOT JUSTIFIED / NOT RUN. Retry: NOT JUSTIFIED / NOT RUN. Larger batch 8: NOT REACHED because the batch candidate failed the semantic gate; no claim about it. No independent holdout, new pipeline candidate freeze, V3, training, R7, production batch switch, release, or model promotion occurred. **RETRAINING NOT YET JUSTIFIED**: retrieval coverage, affectedness, classification, and format failures are still separable only on open development data; there is no independent post-oracle evidence that training is the needed intervention.
